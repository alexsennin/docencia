## ARC Development Standard v1.3.2

Adoptado el 2026-10-06 por solicitud explícita del usuario. ARC Development Standard v1.3.2 reemplaza ALEX DEVELOPMENT STANDARD v1.3.1 como identidad y versión vigentes de la metodología del proyecto. Se conserva la base de reglas operativas ya documentada para modo, riesgo, capacidad, escalamiento, autorización y validación; no se atribuye ningún cambio normativo adicional mientras no se registre la referencia canónica publicada de ARC v1.3.2. `AGENTS.md` es la puerta de entrada y `project-methodology/` conserva la adaptación del producto. La historia ALEX v1.3.1 y las versiones anteriores queda en DEC-004.

El runtime oficial es AXIOM v0.1; Codex CLI es el motor de ejecución y la familia Luna / Sol / Astra se enruta por capacidad. La correspondencia registrada es ROUTER: Luna Bajo; FOCUSED: Luna Alto; ADVANCED: Luna xhigh; EXPERT: Sol Alto; FRONTIER: Astra Alto. AXIOM no configura `OPENAI_API_KEY` y no ejecuta RELEASE automáticamente.

La sesión de Codex de esta adopción no transfiere automáticamente tareas a AXIOM; cualquier invocación debe ser explícita y operar desde la raíz del proyecto. No delegar agentes cuando las instrucciones de la sesión lo restringen. Las microtareas describen comportamientos verificables y transfieren contexto mínimo; la delegación no amplía alcance ni autorización.

Estado del runtime (2026-10-06): `axiom doctor` reportó Codex CLI `0.160.1` y flags disponibles, pero una invocación real falló porque AXIOM pasa `--ask-for-approval`, opción que esta versión no reconoce. No se modificó el ejecutable global; AXIOM no quedó validado para ejecutar tareas desde este entorno.

Adopción documental (2026-10-06): modo SYSTEM, Nivel 1; actualización de identidad, runtime y perfil, sin cambio de código ni de servicios remotos. ALEX v1.3.1 queda como antecedente consultado anteriormente. La referencia canónica pública de ARC v1.3.2 está pendiente de registrar; el usuario definió el nombre y la versión vigentes, y el runtime local AXIOM v0.1 identifica esa compatibilidad. La adopción no activa automatizaciones. Sin commit, push, merge ni despliegue documental.
