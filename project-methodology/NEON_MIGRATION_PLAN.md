## Arquitectura objetivo

```text
Local:      Docker Compose -> Next.js/TypeScript + PostgreSQL 18 con datos sintéticos
Producción: Vercel -> Next.js/TypeScript -> Neon PostgreSQL
Migraciones: SQL versionado y revisado en Git, aplicable de forma repetible
```

Las credenciales de Neon son exclusivamente del servidor. No se habilitará acceso directo desde el navegador. La implementación inicial usará PostgreSQL local antes de cualquier escritura remota.

## Uso del entorno local

```sh
docker compose --env-file docker.env.example up --build -d
docker compose ps
docker compose exec -T web npm run db:migrate
docker compose exec -T web env SEED_LOCAL_CONFIRM=YES npm run db:seed:local
docker compose exec -T web npm run db:smoke
```

La aplicación queda en `http://localhost:13000`; la base se puede inspeccionar localmente en `localhost:15432`. Para detener los servicios sin borrar los datos locales: `docker compose down`. `docker compose down -v` elimina el volumen local y debe usarse sólo cuando se quiera reiniciar esa base sintética.

## Fases y aceptación

1. **Baseline y contratos.** Identificar el código exacto activo en Vercel y Apps Script, reconciliarlo con el checkout, inventariar encabezados vivos y acciones del puente, y registrar reglas de negocio. Aceptación: inventario con fuente y límites claros, sin copiar filas personales a documentos o fixtures.
2. **Esquema y migraciones.** Modelar las entidades relacionales, claves, restricciones, auditoría, trabajos de fondo e índices; revisar las migraciones y cubrir cálculos/reglas con pruebas. Aceptación: aplicar el esquema desde cero en PostgreSQL 18 y repetir la prueba de migración sin pérdida de datos.
3. **Entorno local.** Arrancar aplicación y PostgreSQL con Docker Compose, datos sintéticos y migraciones reproducibles. Aceptación: otra sesión puede levantarlo desde instrucciones, comprobar salud de ambos servicios y ejecutar pruebas sin secretos productivos.
4. **Repositorios y APIs.** Implementar acceso a datos y reemplazar Apps Script por módulos; conservar autorización, validación, zona horaria, transacciones e idempotencia. Aceptación: pruebas por módulo de permisos, entradas inválidas, persistencia y concurrencia.
5. **IA y procesos asíncronos.** Mover Gemini al servidor con secreto en Vercel; reemplazar triggers de Apps Script por cola persistente y worker recuperable. Antes del corte elegir y probar un worker autónomo y su frecuencia. El prototipo local de rúbrica persiste jobs y procesa un alumno por petición autenticada desde la UI; retoma si se vuelve a abrir, pero no avanza con el navegador cerrado.
6. **Importación de ensayo.** Crear respaldo independiente y restaurable de la hoja; importar primero en entorno no productivo; reconciliar conteos y resultados sin registrar PII. Aceptación: restauración probada, diferencias explicadas y cálculos iguales a los casos de referencia.
7. **Pruebas de aceptación.** Probar docente y alumno con identidades/grupos de prueba: sesión, P/I/R, tareas, comentarios, rúbrica, examen, respuestas, reporte y persistencia tras reinicio; probar reintentos, doble envío y permisos.
8. **Corte productivo.** Congelar escrituras, obtener respaldo final, importar delta, validar restricciones/conteos, cambiar configuración de servidor y verificar recorridos en el dominio. Aceptación: pruebas end-to-end aprobadas y reversión documentada que no pierda escrituras posteriores al corte.
9. **Retiro de Apps Script.** Detener triggers y retirar el puente sólo tras confirmar que no quedan consumidores, conservando exportación y código histórico conforme a retención acordada.

## Reglas de seguridad y recuperación

- Usar datos sintéticos en Docker y en ramas no productivas. Las ramas normales de Neon pueden copiar datos del padre; no derivar un entorno de desarrollo con PII escolar.
- Mantener la hoja sin cambios durante desarrollo y ensayos; no hacer dual-write improvisado.
- Separar backups de base de datos de Git, y probar restauración antes del corte.
- No retirar ni invalidar Apps Script, Sheets o credenciales hasta confirmar el nuevo flujo completo.
- Producción se considera migrada sólo tras verificar rutas protegidas, escritura/lectura autenticadas, persistencia real y recuperación.

## Ciclo de intentos de examen del alumno (Docker local)

- Las rutas de inicio, guardado, evento, desbloqueo y envío consultan PostgreSQL cuando `DATA_BACKEND=postgres`; fuera del entorno local, Sheets permanece como backend por defecto.
- `lib/exam-attempt-postgres.ts` guarda el intento y las respuestas antes de evaluar, reanuda intentos abiertos, limita las respuestas a reactivos activos, registra eventos de foco y bloquea el intento, y añade la pausa al tiempo al desbloquear. El envío repetido devuelve el resultado persistido. Las evaluaciones abiertas quedan identificadas y guardadas por intento/reactivo; el error o falta de proveedor conserva el intento provisional para revisión docente. La ruta y acción existente de revisión docente ya usan PostgreSQL; aún falta la aceptación visual completa.

Un error, ausencia de clave o respuesta inválida deja la evaluación durable como pendiente con el intento provisional; una evaluación correcta actualiza la calificación y el estado del intento dentro de una transacción. La UI existente muestra `ProgressOverlay` y actualiza el reporte al terminar.

## Configuración de calificaciones y mantenimiento de actividades (Docker local)

- `savePartialModeInPostgres` valida que el parcial esté abierto y permite únicamente `Promedio` o `Ponderado`; las repeticiones del modo vigente no agregan escrituras duplicadas. `saveTaskWeightsInPostgres` requiere modo ponderado, valida que la selección cubra exactamente las actividades activas del grupo/parcial listas para calificar, que no haya IDs repetidos y que la suma sea 100% (tolerancia 0.01), y guarda/audita dentro de una transacción.
- `cancelClassSessionInPostgres` conserva la sesión y sus registros con estado `Cancelada`, vuelve obsoletas las rúbricas afectadas y audita la operación. `deleteTaskInPostgres` conserva calificaciones/historial y marca la actividad inactiva; ambas acciones son idempotentes. `POST /api/teacher/academic` recalcula y persiste snapshots tras cada mutación.
